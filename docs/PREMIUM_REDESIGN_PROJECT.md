# 成増歯科室キムラ｜高級感のある全面改修プロジェクト（Codex / Astra 実装指示）

## 対象
- 現サイト: https://kinnovationx-star.github.io/kimura-dental-site/
- 参考デザイン・オープニング演出: https://open-rise.jp/
- リポジトリ: https://github.com/kinnovationx-star/kimura-dental-site
- 作業ブランチ: `redesign/premium-visual-overhaul-2026`
- **main は変更禁止。公開サイトは承認後に更新する。**
- プロジェクト目的: 既存の利便性・情報設計を活かし、AIテンプレート感を排除。写真を全面監査・必要箇所刷新し、質感・信頼・美しさが共存する歯科医院の公式サイトへリニューアルする。

## 最重要: リファレンス調査
**作業開始時にブラウザで open-rise.jp をPCとSPで実際に確認すること。** 動画撮影または連続スクリーンショットで初回ロードからメインビジュアル表示まで記録し、以下を整理する。
1. オープニングの初期画面（背景・ロゴ・タイポ・画像の状態）
2. 演出の順序（マスク、ロゴ、テキスト、フェード、スライド、スケール等、実際に観察できるもののみ）
3. 各段階の時間・イージング・重なり方
4. ヒーロー表示へのつなぎ、スクロール開始の動作
5. SP版、再訪、低速回線、reduced-motionの挙動
6. サイト全体の余白・写真トリミング・文字サイズ・見出し・トランジション・カラー構成
**未観察のアニメーションや仕様を「参考サイトと同じ」と推測して作らない。ブラウザで確認できない場合は未確認と記録し、代替演出を独立案として提案する。**
参考サイトのコード・写真・ロゴ・固有コピーを複製しない。演出の考え方を研究し、歯科医院固有の新しいデザインとして制作する。

## コンセプト
「Quiet Confidence — 静かな品格と、身近な安心」
高級ホテルのような過剰な華やかさではなく、上質な医療機関の誠実さ、清潔さ、安心感を第一にする。
- 写真・文字・余白の質で高級感を作る。過剰な影、グラデーション、ガラスモーフィズム、無意味な丸角、無数のカードやバッジは禁止。
- トップに大きな英字を機械的に置く、英語と日本語を毎セクション同じ形式で重ねる、全ブロックを同形カードにする等の「AI生成テンプレ感」を排除。
- 医院のロゴを維持。深いネイビー、オフホワイト、やわらかな青灰、控えめな暖色アクセント。現在の青ブランドとの整合を検証して確定する。
- 見出し Shippori Mincho / Noto Serif JP、本文 Noto Sans JP を候補にし、フォント読み込みと実指定を一致させる。
- PC 1440/1920、タブレット 768/1024、SP 375/390/430で個別に調整。SPはただのPC縮小にしない。

## オープニングアニメーション実装要件（最優先）
実測したopen-rise.jpの「静止→動き→完成」の体験設計を参考に、**オリジナルの歯科医院向け演出**を実装。
- 初回訪問はブランドロゴまたは医院名の上品な出現から始め、メイン画像・コピーが自然に現れてFVへシームレスにつながる。手法は参考サイト観察後に決める。
- ブランドの人格に合わない派手なバウンド、過度なズーム、強い点滅、長い待ち時間は禁止。
- タイムラインは細かく設計するが実用上は短く、ロード待ちを強制しない。画像未読込時の破綻を防ぐ。
- 直リンク、ページ内リンク、戻る操作で誤って再生して閲覧を阻害しない。
- 初回訪問/再訪の演出ポリシーを設計。sessionStorageなどは必要性を検証したうえで採用し、再訪時は短縮/省略案を検討。
- `prefers-reduced-motion: reduce` の場合は直ちに静止完成画面へ。スクリーンリーダーの読み上げやキーボードフォーカスを妨げない。
- アニメーション時のスクロールロック解除漏れ、画面白残り、CLS、重いフィルター処理を防ぐ。
- テスト項目: 初回/再訪、PC/SP、Safari/Chrome、遅い通信、画像404、JS無効、reduce motion、連続リロード、戻る/進む。
- **参考サイトとの比較動画を出力し、演出の感触・違いを明文化する。**

## 画像全面刷新ルール
全ページの画像を一覧化（ページ/セクション/現在のファイル/被写体/文脈適合/画質/用途/採否/代替候補/権利/alt）し、採用/置換を決定する。
- 写真が文章内容と一致しているか厳格に評価。例: インプラントにホワイトニングの汎用笑顔写真を割り当てない。
- 院内・医師・スタッフ・設備・駅からの道順・症例・治療実績を**実際の医院の写真であると偽装しない**。オフィシャル素材がなければ「撮影待ち」と明記し、確認済み素材または適切な抽象・汎用カットを仮使用する。
- 既存の重複画像を整理し、文脈上必要な場合を除いて同じ写真を多用しない。
- 同じ医院の写真に見せるため異なる施設写真を混在させない。モデル写真をスタッフとして表示しない。
- 実在性を伴う写真・診療行為・医療設備は事実確認が取れたもののみ。
- 画像はライセンス/使用範囲を確認、原本/出典/許諾情報を管理。画像生成はイメージカットと明示し、医療行為や院内設備の証拠として使用しない。
- アスペクト比・色温度・露出・余白・視線・被写体の向きを揃え、モバイル用トリミングを個別指定。
- WebP/AVIF, srcset/sizes, width/height, lazy loading, LCPヒーローは優先読込。文字を写真に焼き込まない。

## コンテンツ/UX改善
- サイトマップ・全リンク・全CTAを監査し、予約導線を優先。診療内容、選ばれる理由、院長/スタッフ、設備、アクセス、診療時間、FAQの情報の配置を最適化。
- 「50年の歴史」「駅北口徒歩0分」「21時診療」等の主張は根拠を確認し、事実に基づく表記だけ残す。
- 医師紹介・医院実績・症例・患者の声に架空データは追加しない。
- ホワイトニング/インプラント/いびき治療/マウスピース矯正など診療内容ごとに情報を整理。
- 医療広告ガイドライン、自由診療の費用・リスク・副作用・治療期間、症例画像の要件、誇張表現を確認する。
- Web予約・LINE・電話の遷移先を実地検証。未設定は明示し、偽のボタンを残さない。
- ユーザーが最初の5秒で「どこにある、何を診療する、どう予約する」を理解できる設計。
- ローカルSEO、見出し構造、構造化データ（Dentist等）、meta、OGP、canonical、sitemap、robots、アクセシビリティを監査。

## コード品質
観察済み: `index.html` は約138KBの単一巨大ファイルで、インラインCSS/JSが含まれる。現在 `--main:#1942a8`、`.hdg .en {font-size:104px}`、装飾的なピル型ラベルがあり、一部画像を複数箇所で利用。Google Fonts読み込みと指定（例: Marcellus）に不整合が見られる。
- まず現行の全ルートと機能を棚卸し。静的HTMLで維持するかビルド構成へ移行するか比較し、GitHub Pagesの `/kimura-dental-site/` 配信に確実に対応させる。
- CSSデザイントークン、ページ/セクション別スタイル、JSモジュールを責務分割。必要のないフレームワーク導入はしない。
- ハンバーガー、予約CTA、固定ヘッダー、スムーススクロール、画像表示、内部リンクの挙動を保全。
- 不要コード・使っていない画像・重複読み込み・固定ピクセル依存を整理。
- ブラウザ視覚回帰チェック、Lighthouse/Core Web Vitals、WCAG 2.2 AA を意識した検証。CIやビルドの再現性を担保。

## フェーズと成果物
1. **監査:** PC/SP既存サイトの全画面キャプチャ、reference比較、リンク/写真/コード監査表。事実と推測を分離。
2. **方向性:** デザインコンセプト、配色/タイポ/余白、FV案2～3種類、オープニングアニメーションの絵コンテ＋動作仕様、画像台帳。
3. **実装:** 新FV、トップ全セクション、グローバル要素、下層ページ、画像差替、レスポンシブ、アニメーション。
4. **品質:** PC/SP見た目、操作、性能、医療広告、リンク、画像権利、アクセシビリティのチェック結果と残課題。
5. **レビュー:** 変更ファイル一覧、before/afterキャプチャ、プレビューURL、公開手順、ロールバック方法。
各フェーズで必要な素材不足と意思決定をMarkdownで記録する。制作途中のレビューは歓迎だが、最終承認なくmainへマージしない。
